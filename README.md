# 独棋（Chess Ranger / Solo Chess）

一个基于 Web 的独棋逻辑谜题：按国际象棋规则移动棋子，**每一步都必须吃子**，目标是把盘面吃到**只剩一个棋子**。原生 SVG 渲染，内置回溯求解器、逻辑回放与自定义题板。

![独棋界面](output/playwright/01-builtin.png)

## 启动

```bash
npm install
npm start        # 等开发服务就绪后用默认浏览器打开 http://127.0.0.1:5218/
```

- 端口固定为 **5218**（`package.json` 的 `puzzle.port`，`vite.config.ts` / `scripts/dev.mjs` / `scripts/ui-check.mjs` 同源读取）。
- 也可以用 `npm run dev`（不会自动开浏览器），或 `npm run build && npm run preview` 预览构建产物。
- 开发服务器运行时，题库 / 进度 / 上次题目保存在项目内 `data/` 目录；静态部署时自动降级到浏览器 localStorage。

## 游戏规则

- 棋子：兵、马、象、车、后、王（本作统一为同一方棋子，见「已知限制」）。
- 每一步都必须按该棋子的**标准走法吃掉另一个棋子**，不能走空步。
- 允许吃王；没有将军 / 将死 / 王车易位等限制。
- 兵只朝「上」斜吃一格（本作约定），不升变。
- 车 / 象 / 后沿直线或斜线吃子时路径不能有其它棋子；马可以跳过棋子。
- 当盘面只剩 1 枚棋子时通关；如果还剩多枚却无子可吃，则进入死局（可撤销重来）。
- 坐标约定与棋盘标注一致：`a1` 在左下角，列字母 a–j、行号 1–8 从下往上。

## 操作

| 操作 | 说明 |
|------|------|
| 左键点棋子 | 选中棋子，所有可吃目标会高亮（红圈） |
| 左键点高亮目标 | 执行吃子（攻击方落到目标格，被吃棋子消失） |
| 左键点空格 / 不可吃目标 | 状态栏给出非法走法提示（红色虚线 + ×） |
| 右键 | 取消选中 |
| 方向键 | 移动键盘光标（蓝色虚线框） |
| 回车 / 空格 | 选中光标处棋子；已选中时在光标处吃子；再按一次取消选中 |
| Esc | 取消选中 |
| Z / Shift+Z / Y | 撤销 / 重做 |
| C | 检查盘面（剩余棋子数、历史合法性、是否通关） |
| H | 提示一步（求解器给出当前盘面可行的下一步） |
| S | 显示解（直接填入通关终局） |
| L / P | 逻辑解题回放 / 暂停继续 |
| R / M | 随机抽题 / 音效开关 |
| 滚轮 / 拖拽 / `+` `−` `0` | 缩放 / 平移 / 复位视图 |
| 清空按钮 | 回到题面初始布局 |

## 校验与提示

- **实时校验**：每次落子后重新校验，并显示剩余棋子数、已吃步数、当前可吃子数量。
- **逐步合法性**：状态里保存完整吃子历史，校验时从初始布局逐步重放，确认每一步都是合法吃子、盘面与历史一致。
- **通关判定**：重放后恰好剩 1 枚棋子。
- **提示一步**：从当前盘面调用求解器（带节点数与时间预算），给出能走向胜利的一步，并自动执行。
- **显示解**：内置题直接重放内置参考解；自定义题现场求解后填入终局。

## 自定义题板

侧边栏「自定义」打开编辑器（复用模板的 cell 模式，格子值 = 棋子编码）：

- 点击格子循环：空 → 兵 → 马 → 象 → 车 → 后 → 王 → 空；
- 键盘 `1`–`6` 直接放对应棋子，`0` / 退格清空，方向键移动、右键清空格子；
- 宽高范围 3–10 × 3–8（默认 5×5），「生成网格」重开题板；
- **载入题板**：把当前题板载入棋盘并存入题库（可重复游玩）；
- **保存到题库**：保存 / 覆盖当前题板（题库条目带「编辑」「×」按钮）；
- **求解**：对自定义盘面跑回溯求解，成功则直接填入通关终局，并在面板里显示搜索节点；
- 题库中的自定义题支持**再次编辑**（题面回填编辑器）与**两步确认删除**。

## 内置题库

共 8 道，均经脚本审计「有解且解唯一」：

| 题目 | 尺寸 | 棋子 | 步数 |
|------|------|------|------|
| 四子小试 | 4×4 | 4 | 3 |
| 双象奇袭 | 4×4 | 5 | 4 |
| 马踏连营 | 5×5 | 5 | 4 |
| 车行直道 | 5×5 | 6 | 5 |
| 后王协奏 | 6×6 | 6 | 5 |
| 斜线突进 | 6×6 | 7 | 6 |
| 七子迷阵 | 7×7 | 7 | 6 |
| 八子终局 | 8×8 | 8 | 7 |

题库由 `scripts/gen-puzzles.mjs` 反向生成（从「剩 1 枚」的终局反向拆解），再用求解器做唯一性审计，只保留唯一解题目。

## 技术实现

- `src/game/rules.ts`：走法几何（兵/马/象/车/后/王）、吃子合法性、合法走法枚举、盘面编码。
- `src/game/solver.ts`：DFS 回溯吃子序列；**状态记忆化**（同一盘面结果缓存）、**死路剪枝**（无子可吃即失败）、**MRV 排序**（可吃子最少的棋子先试）、**节点数 + 墙钟双重预算**；`countSolutions` 用于唯一性审计。
- `src/game/logic.ts`：把搜索步骤包装成 `LogicPlan` / `PlaybackFrame` 逐帧回放；每步再用求解器判定是否「唯一可行吃子」，否则标注「搜索」。
- `src/game/validate.ts`：剩余棋子数、逐步重放合法性、通关判定与状态栏文案。
- `src/game/render.ts`：SVG 棋盘（深浅格 + 文件/行号）、棋子字形、选中/可吃目标/非法走法/键盘光标、吃子轨迹与涟漪特效。
- `src/game/state.ts`：状态、吃子 Move（`meta.kind = capture/uncapture`）、撤销/重做、存档、序列化。
- `src/core/app.ts` 为本作新增了**选择式交互**扩展：适配器可选实现 `clickAt` / `keyAt`，核心负责记录撤销、存档、重绘、状态栏与特效；旧游戏不使用这些可选接口，行为不变。

## 已知限制

- 棋子统一为同一方（白方），因此兵只朝上斜吃、不升变；没有黑白交替吃子等变体。
- 不实现将军 / 将死 / 王车易位 / 吃过路兵等完整对局规则（本谜题也不需要）。
- 逻辑回放是「搜索 + 唯一可行判定」的包装，不是人类式局部推理；复杂题会标注为「搜索」。
- 自定义题板只限制尺寸，不强制唯一解；可用「求解」按钮检查是否有解（无解 / 超时会给出提示）。
- 求解预算：显示解 / 自定义求解 6 秒、约 150 万节点；超大自定义题可能超时。
- 存档会保存当前吃子历史与选择无关的状态，刷新可继续；编辑自定义题后旧进度可能提示「历史校验失败」，清空即可。

## 图片识图导入

```bash
# 预览：识别棋盘与棋子，不写入题库
npm run import-image -- month.png

# 识别并追加到题库（会写入一条参考解）
npm run import-image -- month.png --append --name "识图 · 8×8" --verify

# 识别簇不确定时人工指定：簇号=棋子编号（1 兵 2 马 3 象 4 车 5 后 6 王）
npm run import-image -- month.png --map 4=1 --map 0=3
```

| 参数 | 说明 |
|------|------|
| `--name 名称` / `--id ID` / `--series 系列` | 题库条目信息 |
| `--append` | 写入 `src/game/puzzles-data.ts` |
| `--verify` | 额外校验解是否唯一（不唯一/超时只警告） |
| `--map 簇号=棋子` | 人工覆盖字形识别结果，编号 1..6 |
| `--budget N` | 求解节点上限 |
| `--dry` | 只识别并打印盘面，不求解、不写入 |

- 识别原理：按深浅格配色自动找到棋盘矩形、按颜色跳变数行列（3..10 × 3..8）→ 每格用主色做背景差取棋子墨迹 → 归一化 32×32 → 字形聚类 + 内置 lichess/cburnett 风格棋子轮廓模板 IoU 分类。
- 内置模板是标准国际象棋轮廓，白/黑棋子通用；其它棋子字体识别率会下降，用 `--map` 按“簇号=棋子编号”覆盖即可。
- 题库要求每道题自带一条合法吃子序列：识别后必须能求出解才会导入；无解时先用 `--map` 修正识别。
- `npm run gen` 会覆盖 `puzzles-data.ts` 中的导入内容。
